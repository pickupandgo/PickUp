# Authenticated Driver location contract

The Engine remains the owner of operational locations, trip assignment and dispatch. No money or Backend database access is introduced. The additive migration `20261101120000_driver_positions` stores one latest GPS fix per Firebase subject in the existing Engine PostgreSQL database, shared across Engine app instances.

`PATCH /drivers/:subject/location` requires the existing Firebase bearer verification and exact caller/path identity match. Body: `{ latitude, longitude, capturedAt, accuracy, tripId? }`; capture time is original GPS UTC epoch milliseconds, accuracy meters, and optional trip ID the Engine UUID. Reject unknown fields, non-finite/out-of-bounds coordinates, accuracy outside 0–100 m, captures older than 30 seconds or more than 5 seconds in the future. An active persisted Driver assignment proves trip ownership; an optional mismatched trip fails 403. Outside a trip, Backend Driver eligibility remains mandatory. Uploads never advertise availability. Busy availability=true requests remain unavailable and dispatch still excludes active trips and requires eligibility.

Atomic conditional PostgreSQL upserts apply only strictly newer captures. Success is `{ success:true, driver:{ id, accepted, capturedAt } }`; duplicate/older requests acknowledge `accepted:false` without replacing the latest fix.

`GET /drivers/:subject` permits the Driver themselves or the Customer of their active assigned trip. Success preserves `{ success:true, driver:{ id, latitude, longitude, ... } }`, adding `capturedAt` epoch milliseconds, `receivedAt` ISO UTC, `accuracy`, capture-time `lastSeen`, and `locationStatus:'LIVE'`. Unrelated identities get 403. Unknown/expired fixes get 404 with top-level `code:'LOCATION_UNAVAILABLE'`. A fix expires from all reads after 60 seconds, including after restart; no default coordinate is live. `GET /drivers` is limited to the caller's own current fix, preventing arbitrary full enumeration. Nearby available-driver discovery remains the existing dispatch contract, with fresh positions and busy-driver exclusion.

Before any separately authorized deployment, apply the new migration and ensure the Engine runtime role has SELECT/INSERT/UPDATE on `engine_driver_positions`. Keep clocks synchronized. Coordinate Driver rollout: old lat/lng-only publishers do not satisfy the new freshness contract and are rejected. Do not alter old migrations or reset data. A fresh fix survives an Engine app restart only if the same database is used; a lost/unavailable database never yields a fabricated live point. One latest row is retained per subject; expiration is enforced at reads, and retention/deletion policy needs review before public distribution.

The shared GPS store does not redesign existing process-local dispatch presence/vehicle display metadata. Horizontal dispatch ownership and load capacity remain separate release checks. No new Redis service or other infrastructure was added. Engine lifecycle, OTP, payment gates and financial behavior are unchanged.

Local verification uses synthetic fixtures only. Set `ENGINE_TEST_DATABASE_URL` to an isolated disposable database ending `_test` (the test setup clears that database). Use UTC as required by existing timestamp-based test fixtures. Unit tests, full Engine integration tests, duplicate/late writes, unavailable positions, active-trip availability isolation, assigned-Customer reads and independent Engine-app recovery were exercised. Staging/device restart testing still requires release authorization.
